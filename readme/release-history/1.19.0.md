# 1.19.x

**BoxLang 1.19.0** adds a place for your own global settings, built-in **code coverage and execution profiling**, **static method interception**, **raw binary HTTP streaming**, and the missing **post-invocation events for BIFs**. It also brings a new key pair generator, a round of class-resolution and string performance work, and a long list of CFML-compatibility, `cftranspile` and database fixes.

{% hint style="warning" %}
**This release is unreleased and these notes are in progress.** Items are added as they are merged to `development`.
{% endhint %}

{% hint style="success" %}
## 🎛️ NEW: Your Own Global Settings in `boxlang.json`

**Store your own named values in `boxlang.json` and override them per application.** The new `runtimeSettings` struct takes values of any type, resolves `${env.X}` placeholders and `bxsecret:` secrets at any depth, and is read with the new [`getRuntimeSetting()`](../../boxlang-language/reference/built-in-functions/system/GetRuntimeSetting.md) BIF. Read the [Runtime Settings guide](../../getting-started/configuration/runtime-settings.md).
{% endhint %}

## 🚀 Major Highlights

### 🎛️ Runtime Settings (BL-2762)

A user-defined struct in `boxlang.json` that belongs to your applications. BoxLang loads and serves it, it never interprets it.

{% code title="boxlang.json" %}
```json
{
    "runtimeSettings": {
        "apiUrl": "${env.API_URL:http://localhost:8080}",
        "stripeKey": "bxsecret:AbC123...",
        "features": { "beta": true, "regions": [ "us", "eu" ] }
    }
}
```
{% endcode %}

* **Any value type.** Strings, numbers, booleans, structs and arrays, with unique keys.
* **Environment variables and secrets.** `${env.VAR}`, `${env.VAR:default}`, the path variables and `bxsecret:` values resolve at any depth, including inside arrays.
* **Application overrides.** `this.runtimeSettings` in `Application.bx` (or `bx:application runtimeSettings={...}`) is **deep merged** over the global values and the application wins by key. Arrays and scalars are replaced, not merged. The Application layer re-resolves placeholders and secrets on **every request**, and is cached for the rest of that request.
* **Read only.** Returned structs and arrays are deeply unmodifiable.

```js
// Application.bx
class {

    this.name = "myApp"

    this.runtimeSettings = {
        features : { level : 7 }
    }

}

getRuntimeSetting( "features.level" )          // 7, from the application
getRuntimeSetting( "features.beta" )           // true, from boxlang.json
getRuntimeSetting( "features.regions.1" )      // "us", array indexes are 1-based
getRuntimeSetting( "timeout", 30 )             // default when missing
getRuntimeSetting()                            // the whole merged struct
```

A missing key with no default throws, the same convention as `getSystemSetting()`. See [Runtime Settings](../../getting-started/configuration/runtime-settings.md) and the [Application.bx](../../boxlang-framework/applicationbx.md#runtime-settings) settings.

### 📈 Code Coverage and Execution Profiling (BL-2732)

BoxLang can now record **which code ran, how often, and where the time went** while your code executes, with no changes to that code.

* **Coverage.** Per file, whether each executable span ran (covered or missed) and how many times.
* **Timing.** Accumulated self time per span, so hot code is easy to find.
* **Fine grained.** Branches, short-circuit operators, ternaries, function and closure bodies and class code are tracked independently, so you can see which branch actually ran.
* **Aggregation.** Covered, executable and total counts, and a coverage percentage, across files.
* **Exports.** Built-in export to **JSON** (per line or per span) and **SonarQube generic coverage XML** for CI, plus **HTML** reports for line coverage, spans and a span **heatmap**.
* **Off by default.** Capture is a single flag, and nothing is instrumented when it is off.

{% code title="boxlang.json" %}
```json
{
    "codeProfilerEnabled": true
}
```
{% endcode %}

The collected data is exposed through the runtime's `CodeProfilerService`, which coverage reporters and CI exporters consume.

### 🧩 Static Method Interception: `onMissingStaticMethod()` (BL-2748)

Classes have always had `onMissingMethod()` for instance calls. Static calls to a method that does not exist used to throw a `KeyNotFoundException`. A class can now handle them, which enables dynamic static APIs such as `User::findByEmail( "a@b.com" )`.

```js
class {

    static function onMissingStaticMethod( string missingMethodName, struct missingMethodArguments ){
        return "called #missingMethodName#"
    }

}

MyClass::anything( 1, 2 )    // "called anything"
```

* It runs only when the static method is **missing**, so normal static calls cost nothing extra.
* It runs as a static function of the class, with `static` access like any other static call.
* It works when declared in the class **and** when a module adds the function to a class's static scope at runtime.
* A handler can cache by putting a function into the static scope under the missing name, so later calls are normal static calls.
* It also works for classes that **extend a Java class**. A call is only sent to the Java parent when the parent has a matching method, otherwise it falls through to the missing-method handlers.
* Without a handler, behavior and error messages are unchanged.

See [Static Constructs](../../boxlang-language/classes/static-constructs.md).

### 📡 Raw Binary HTTP Streaming: `onBinaryChunk` (BL-2738)

`http().onChunk()` decodes the body as text and splits it on newlines, which corrupts binary streams such as audio. The new `onBinaryChunk` callback receives **raw bytes per network read**.

```js
http( url, "POST" )
    .header( "Authorization", "Bearer #key#" )
    .body( payload )
    .timeout( 30 )
    .onBinaryChunk( ( bytes, info ) => {
        sendToClient( bytes )
        return !clientGone    // an explicit false stops the stream and closes the connection
    } )
    .onError( ( e, result ) => handleError( e ) )
    .send()
```

* `info` carries `chunkNumber`, `totalBytes`, `headers` (first chunk only), `result` and `httpClient`.
* **Stop on `false`.** Only an explicit `false` stops the stream. The response is closed immediately and the result is flagged as not completed, not as an error.
* **Idle timeout for streaming.** In binary and SSE modes `timeout` becomes the longest wait for headers or between received bytes. A stalled stream is reported as a timeout error (408). Buffered mode is unchanged.
* **Errors.** In binary and SSE modes a non-2xx status skips the chunk callback, and the body is reported as `HTTP <status>: <body>` through `onError` and the result struct.
* **SSE.** Server-sent events get the same stop-on-false, idle timeout and non-2xx handling, and now apply `Content-Encoding` decoding.
* Also available as an attribute on `bx:http`. Fully backward compatible.

See [HTTP Calls](../../boxlang-framework/http-calls.md) and [Server-Sent Events](../../boxlang-framework/server-sent-events.md).

### 🔔 BIF Interception Points Fixed (BL-2741)

`postBIFInvocation` was declared but never announced, and `onBIFInvocation` fired twice per call. BIF invocation now mirrors user-defined functions:

| Point | When | Data |
| ----- | ---- | ---- |
| `onBIFInvocation` | Once, before the call | `context`, `arguments`, `bif` and `name` |
| `postBIFInvocation` | After a successful call | The same data plus `result` and `elapsedNanos`. Listeners may override `result` |
| `onBIFException` | New. When the BIF throws | `exception` and `elapsedNanos`. The exception is rethrown unchanged |

With no listeners registered there is no allocation and no clock read on the hot path. See [Life-cycle Events](../../boxlang-framework/interceptors/core-interception-points/life-cycle-events.md).

### 🔑 `generateKeyPair()` (BL-2753)

A new BIF next to [`generateSecretKey()`](../../boxlang-language/reference/built-in-functions/encryption/GenerateSecretKey.md) for **asymmetric key pairs**, with no Java interop needed.

```js
pair = generateKeyPair( "Ed25519" )
pair.publicPem
pair.privatePem
```

* **Algorithms:** `Ed25519`, `Ed448`, `X25519`, `X448`, `RSA` (2048, 3072, 4096) and `EC` (`secp256r1`, `secp384r1`, `secp521r1`).
* **Returns a struct** with `algorithm`, `privateKey` (base64 PKCS8 DER), `publicKey` (base64 X.509 SPKI DER), `privatePem` and `publicPem`.
* **Randomness** comes from the JDK `SecureRandom`, supplemented with the runtime's global secret seed.

## ✨ New Features and Improvements

### Language and Runtime

* **Static assignment from outside a class (BL-2749).** `Foo::counter = 42` now assigns a static variable. It used to throw `KeyNotFoundException`.
* **`static[ name ] = value` (BL-2750).** Writing to the static scope with bracket notation inside a function is no longer parsed as an array destructuring declaration.
* **Thread scope removed from unscoped lookup (BL-1792).** See the [Migration Notes](#-migration-notes).
* **Better nested database exceptions (BL-2743).** SQL exceptions can chain many additional exceptions. A cause that was already set no longer makes the chain throw. It is stored as a suppressed exception, which still shows in the stack trace.

### Caching

* **`systemCacheClear( "classfiles" )` (BL-2714).** Clears the compiled class files cached on disk. See [SystemCacheClear](../../boxlang-language/reference/built-in-functions/system/SystemCacheClear.md).

### JDBC and Queries

* **Stored procedure debugging (BL-2715).** With `debug=true` the log now shows which variables and types were created from which `OUT` parameter names.
* **Transactions roll back on `abort`.** A database transaction is now properly rolled back when `abort` is hit inside it.

### Performance

* **Class lookups (BL-2747).** The class resolver no longer lists every directory on the path for each lookup miss. On case-sensitive file systems the cost grew with the number of class files, because every extension tried before the real one was a miss. Class resolution is no longer quadratic.
* **`replace()` and `replaceNoCase()` (BL-2756).** Refactored to avoid allocating substrings.
* **Date comparisons (BL-2758).** Comparisons pass the caller's context down to the date caster, so a date compare no longer rebuilds the whole runtime config struct. A date string compared inside a request is also read in the **request** timezone. Java integrators: `Compare` and the comparison operators gain context-taking overloads, and the old ones are deprecated.
* **Interceptor announcements (BL-2759).** Interceptors announced without a context (BIF, query and transaction events) now run on the **current request** when there is one. They see its settings and no longer rebuild the runtime config on every read.

### Casting

* **BigDecimal and BigInteger (BL-2730).** A string with leading whitespace before the number, such as `" 1"`, now casts.

### Tooling

* **`cftranspile` fixes (BL-2735, BL-2736).** Docblock `@return` no longer becomes an invalid annotation, script components written without a `bx:` prefix (`savecontent`, `application`) now compile, and tag-form `<cffunction>` in `.cfm` templates is emitted as `bx:function` instead of being silently dropped. Template conditions print `GT` and `GTE` as keywords, and `NOT CONTAINS` as `DOES NOT CONTAIN`.

## ⚡ Migration Notes

* **Thread scope and unscoped lookup (BL-1792).** Inside a `thread` body, an unscoped name no longer falls back to the thread's metadata struct. Adobe ColdFusion and Lucee do not do this either. In practice:
  * `foo` no longer resolves after `thread.foo = "bar"`. Use `thread.foo`.
  * Unscoped reads no longer pick up metadata keys such as `status` or `output`.
  * An unscoped assignment such as `status = "x"` now goes into the local scope instead of the thread metadata.

  Scoped access (`thread.foo`, `myThread.foo`, `bxthread.myThread.foo`) and request-level access by thread name are unchanged.
* **Date strings in comparisons (BL-2758).** A date string compared inside a request is now read in the request timezone rather than the runtime default timezone.
* **Java integrators (BL-2758).** The `Compare` and comparison operator methods without a context are deprecated in favor of the context-taking overloads.
* **`onBIFInvocation` (BL-2741).** It now fires once per call, not twice. If you worked around the duplicate, remove the workaround.
