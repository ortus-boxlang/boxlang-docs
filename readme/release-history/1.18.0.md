## 🚀 Major Highlights

### Fixed: CF-Transpiled `cflock type="exclusive"` Is Exclusive Again (BL-2686)

The CFML transpiler's `cflock`/`lock` fix-up logic mapped `type="write"` to `exclusive`, then mapped **every other value that wasn't `"readonly"`** down to `"readonly"` — which caught `"exclusive"` itself. Any CFML-source lock written with `type="exclusive"` therefore compiled down to a **read lock**, silently losing mutual exclusion.

The blast radius is every CF-source exclusive lock, including WireBox's `Singleton.cfc` double-checked-locking scope, where the lock is the only thing preventing duplicate singleton construction under concurrency. Verified on a 64-thread probe: from `.bxs` source, the maximum number of threads simultaneously inside the "exclusive" section stayed at `1` (correct); from CF source, it reached `18`-`29`.

The mapping is now:

* `write` → `exclusive`
* `exclusive` (any case) → stays `exclusive`
* `readonly` → stays `readonly`
* anything else → `readonly` (CF's lenient default)

{% hint style="danger" %}
If you run CFML source through BoxLang's CF transpiler and rely on `cflock type="exclusive"` for mutual exclusion — including indirectly, through libraries like WireBox's singleton scope — this fix restores correctness. See [Migration Notes](#-migration-notes) below.
{% endhint %}

## 🤖 Core Runtime Updates

### New Date Unit Setter BIFs and Member Methods (BL-2689)

You can now set a single unit of a date/time value — year, month, day, hour, minute, or second — without reconstructing the whole date. Every unit is available both as a `dateSet*()` BIF and as a member method on the date object, and both mutate the date in place and return it:

```js
someDate = now()

// Member method syntax
someDate.setYear( 2027 )
someDate.setMonth( 6 )
someDate.setDay( 15 )

// Equivalent BIF syntax
someDate = dateSetHour( someDate, 14 )
someDate = dateSetMinute( someDate, 30 )
```

Out-of-range values roll over into the next unit (`setDay( 50 )` advances into following months), while zero/negative values clamp to the first valid unit (`setDay( 0 )` becomes day `1`).

### Thread Metadata Is Now Computed on Read, Not Tracked Continuously (BL-2696)

`bx:thread`'s exposed metadata — a thread's `status`, `elapsedTime`, and `stackTrace` (available as `thread.status` inside the thread itself, or `myThread.elapsedTime` / `bxthread.myThread.stackTrace` anywhere in the request) — is now computed lazily when read, instead of being tracked continuously while the thread runs. A stack trace is expensive to capture, and a running thread previously paid part of that cost on every unscoped variable lookup; now it's only paid when something actually reads the metadata. Every other metadata key remains a plain stored value, and once a thread completes, its final status/elapsed time/stack trace are stored so nothing is recomputed after the fact.

### `BoxFuture.allApply()` Without an Error Handler (BL-2685)

`BoxFuture.allApply()` — the helper that runs a mapper function over every item in an array or struct concurrently — now has an overload that doesn't require you to pass an error handler:

```js
results = BoxFuture::allApply( myArray, ( item ) => processItem( item ) )
```

### JDBC: Optional Boolean Representation for `BIT` Columns (BLMODULES-300)

`GenericJDBCDriver` gains a `representBitAsBoolean` flag. When enabled, a JDBC `BIT` column is represented as a true BoxLang boolean instead of the numeric `1`/`0` BoxLang has always used for `BIT` columns — a follow-up to the `1.17.4` fix (BL-2674) that made bit-casting consistent across database drivers.

### Fixed: Race Condition Merging Inherited Class Properties (BL-2628)

Property merging from a parent class into a subclass now happens exactly once per class, even under concurrent access. Previously, two threads instantiating the same class for the first time at nearly the same moment could both perform the merge, which was wasted work at best and a data race at worst; `IClassRunnable` now tracks whether the merge has already happened and skips it on subsequent instantiations.

### Faster `replace()` for Whole-String Replacements (BL-2697)

`replace( string, substring, replacement, "all" )` now early-exits immediately when the target substring never appears in the source string, and avoids repeated substring allocation while scanning for matches — a meaningful speedup on large strings with no (or few) matches.

## 🐛 Notable Bug Fixes

* [**BL-2686**](https://ortussolutions.atlassian.net/browse/BL-2686) — See [Major Highlights](#-major-highlights) above: CF-transpiled `cflock type="exclusive"` no longer silently downgrades to a read lock.
* [**BL-2694**](https://ortussolutions.atlassian.net/browse/BL-2694) / [**BL-2963**](https://ortussolutions.atlassian.net/browse/BL-2963) / [**BL-2964**](https://ortussolutions.atlassian.net/browse/BL-2964) — `numberFormat()`: fixed padding not being fully retained in the final formatted number, plus additional Adobe/Lucee compatibility, rounding, and formatting corrections.
* [**BL-2691**](https://ortussolutions.atlassian.net/browse/BL-2691) — JDBC query parameters: date detection now recognizes any known Java date/time type (not just BoxLang's own `DateTime`) when inferring the SQL type for a bound parameter; fixed a related column-type lookup bug in `Query` that could misidentify a column's SQL type when a result set contained duplicate column labels. Includes new MSSQL driver test coverage.
* [**BL-2683**](https://ortussolutions.atlassian.net/browse/BL-2683) — `BoxFile`/`fileRead()`/`loop file=...`: reading a file no longer silently stops (treating it as EOF) the moment it hits a byte sequence that isn't valid in the configured charset. Invalid sequences are now replaced with the Unicode replacement character instead, and a genuine I/O error is now thrown rather than swallowed as EOF.
* [**BL-2684**](https://ortussolutions.atlassian.net/browse/BL-2684) — `bx:transaction` / `cftransaction`: fixed `action="begin"` detection to match the action exactly instead of inferring it from the presence of a tag body, corrected commit/rollback/cleanup ordering, and non-begin actions (`commit`, `rollback`, `setsavepoint`) now silently no-op when there's no active transaction, matching CF engine behavior instead of throwing.

## ⚡ Migration Notes

* **`cflock type="exclusive"` is now actually exclusive.** If your CF-transpiled code (or a library it depends on, such as WireBox's singleton locking) relies on `type="exclusive"` for mutual exclusion, it will now correctly block concurrent access after upgrading. If any of that code was inadvertently relying on the previous broken (non-exclusive) behavior — for example, tolerating concurrent execution inside what was supposed to be an exclusive section — re-verify it under load; you may see more lock contention now that exclusivity is actually enforced.
* **Invalid characters no longer truncate a file read.** If code reading a file via `BoxFile`, `fileRead()`, or `loop file=...` was depending on the previous (incorrect) behavior of silently stopping at the first byte sequence invalid for the configured charset, it will now continue reading with the Unicode replacement character (`�`) substituted in for those bytes instead.
